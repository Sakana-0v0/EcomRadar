## 评测基线解读

### 为什么 EM=0%?
本 baseline 评测的是 **RAG 检索链路** (BM25 + Dense + Rerank),它返回的是**上下文文档**而不是**精炼答案**。
例如:问题"小度智能音箱价格?",baseline 返回 KB 文档 "智能音箱是 AI 语音助手载体,主流品牌有小度、天猫精灵、小爱",而非"329元"。

**这是预期的**:RAG 的输出是 LLM 的输入,精确答案应由 Writer 节点生成。

### F1=0.16 表示什么?
- 检索内容与问题在**主题上相关** (F1 > 0)
- 但**未直接包含答案** (F1 较低)
- 这验证了检索系统能"找到相关文档",但需要 LLM 进一步"抽取答案"

## 端到端延迟分析

- **P50**: 2.6 秒 (单次查询中位耗时)
- 主要耗时在 embedding API 调用
- 50 条 benchmark 总耗时约 130 秒(并发度=1)

## 优化方向(后续 Phase 9 可对比)

1. **Embedding 缓存**: 同 query 复用结果
2. **BM25 调权**: 提高精确数字匹配权重
3. **多路召回**: 检索+工具调用组合
4. **LLM 抽取**: 检索后用 LLM 抽取精确答案(再跑 Writer variant)
